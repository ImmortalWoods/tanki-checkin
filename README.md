# tanki-checkin

Забирает ежедневные награды «табеля» на https://tanki.su/ru/daily-check-in, чтобы
не приходилось помнить про отдельную страницу. Работает на Windows и Linux.

Скрипт открывает страницу в headless-Chromium на сохранённом профиле и повторяет
ту же последовательность запросов, что и сам виджет календаря: серверное время →
токен месяца → сколько дней уже забрано → что доступно сегодня → забор.

Запросы идут через API, а не кликом по кнопке: бандл виджета пересобирается
каждый месяц, а классы вёрстки захешированы — селекторы отваливались бы первого
числа.

Авторизация — только cookie сессии. Она живёт в персистентном профиле Chromium,
никаких паролей скрипт не хранит и никуда не отправляет.

## Требования

- Windows 10/11 или Linux с systemd.
- Python 3.10+ и Playwright:

```
pip install -r requirements.txt
python -m playwright install chromium
```

Второй командой ставится сам браузер — без неё скрипту нечего запускать.

На Windows ставь Python с python.org и отметь галочку «Add python.exe to PATH» —
иначе установщик задач его не найдёт.

## Установка

**Windows**

```
cd tanki-checkin

python login.py main                     :: 1. вход руками, откроется браузер
python checkin.py --dry-run -v           :: 2. холостой прогон
python checkin.py -v                     :: 3. настоящий прогон
windows\install.cmd                      :: 4. автозапуск (от администратора)
```

**Шаг 4 запускай от имени администратора** — правой кнопкой по `install.cmd` →
«Запуск от имени администратора». Задача «при входе в систему» регистрируется на
уровне системы, и без повышенных прав планировщик её не создаст. Если запустить
обычным пользователем, установщик так и скажет и ничего не сделает. Первые три
шага прав не требуют.

`install.cmd` заводит две задачи в планировщике: ежедневно в 09:00 и при входе в
систему. Окна консоли не появляется — задача запускается через `pythonw`, а всё,
что произошло, видно в логе и в уведомлениях.

**Linux**

```bash
cd tanki-checkin

./login.py main                  # 1. вход руками, откроется браузер
./checkin.py --dry-run -v        # 2. холостой прогон
./checkin.py -v                  # 3. настоящий прогон

# 4. автозапуск: при входе в сессию и ежедневно в 09:00
mkdir -p ~/.config/systemd/user
sed "s|/path/to/tanki-checkin|$PWD|g" systemd/tanki-checkin.service \
    > ~/.config/systemd/user/tanki-checkin.service
cp systemd/tanki-checkin.timer ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now tanki-checkin.timer
systemctl --user enable tanki-checkin.service
```

Шаги 2 и 3 не пропускай ни на одной из систем: пока не увидишь успешный реальный
прогон, включать автозапуск незачем.

## Важное: забор — половина дела

Правила календаря, спрятанные в бандле виджета:

> «Если вы забрали награду в календаре, но **не зашли в игру до 3:00 (МСК)
> следующего дня, награда не будет доставлена**. Пока вы её не заберёте, награда
> следующего дня не откроется.»

Скрипт закрывает первую половину — забор на сайте. Вторую, заход в игру, делаешь
сам: после успешного забора приходит уведомление «зайди в клиент», а на
следующем прогоне скрипт сверяет счётчик доставленных дней и скажет, если
награда всё-таки пропала.

## Несколько аккаунтов

Аккаунт — это отдельный профиль Chromium. Сессии друг друга не затирают, поэтому
аккаунтов может быть сколько угодно. Отдельного файла-реестра нет: список
подкаталогов `profiles/` и есть реестр.

```
login.py                 показать заведённые аккаунты
login.py второй          завести новый или перелогинить существующий
checkin.py --list        аккаунты, дата последнего забора, простой
checkin.py               прогон по всем сразу
checkin.py --account второй --dry-run -v    только один, вхолостую
```

(на Linux — `./login.py`, на Windows — `python login.py`)

Аккаунты идут последовательно, с паузой в пять секунд. Сбой на одном не мешает
остальным: прогон доходит до конца, уведомление приходит одно на всех со сводкой.

Временно исключить аккаунт, не удаляя профиль, — положить в его каталог пустой
файл `.disabled`.

## Повседневное

**Windows**

```
schtasks /run /tn TankiCheckin      :: забрать прямо сейчас
schtasks /query /tn TankiCheckin    :: когда следующий запуск
windows\uninstall.cmd               :: убрать из автозапуска
```

Лог: `%LOCALAPPDATA%\tanki-checkin\state\log`

**Linux**

```bash
tail -f ~/.local/state/tanki-checkin/log     # что происходило
systemctl --user list-timers tanki-checkin*  # когда следующий запуск
systemctl --user start tanki-checkin.service # забрать прямо сейчас
journalctl --user -u tanki-checkin -n 50     # вывод последних запусков
```

Успешный забор проходит молча, только строкой в логе. Уведомление появляется
только при проблеме.

## Что может сломаться

| Уведомление | Что случилось | Что делать |
|---|---|---|
| «нужен повторный вход» | сессия tanki.su истекла | `login.py <имя>` |
| «сервер ответил неожиданно» | Lesta поменяла API | смотреть сырой ответ в логе |
| «не удалось достучаться» | сеть недоступна | проверить связь, запустить руками |
| «награды давно не приходят» | больше трёх дней без забора | смотреть лог, скорее всего сайт изменился |
| «зайди в клиент» | награда забрана и ждёт доставки | зайти в игру до 3:00 МСК |
| «награда не доставлена» | в клиент не зашли вовремя | награда пропала, следующий день не откроется |

Сессия истекает сама по себе примерно раз в две недели, даже если cookie ещё не
просрочена — это нормально, лечится повторным входом.

Пустой список наград сам по себе не ошибка (например, за сегодня уже забрано),
поэтому сырой ответ сервера пишется в лог всегда, когда скрипт решает ничего не
забирать. По нему и разбираться.

## Тесты

```
pip install -r requirements-dev.txt
python -m pytest test_logic.py -v
```

Чистая логика без сети и браузера: токен месяца, выбор дня, разбор ответов,
распознавание разлогина, а также различия платформ — пути, User-Agent и способ
показать уведомление.

## Где что лежит

```
checkin.py        ежедневный забор
login.py          разовый ручной вход
run_daily.sh      обёртка для systemd
platform_bits.py  всё, чем Windows отличается от Linux
test_logic.py     тесты
requirements.txt  зависимости
windows/          установщик задач планировщика
systemd/          юниты автозапуска
```

| | Windows | Linux |
|---|---|---|
| профили с cookie | `%LOCALAPPDATA%\tanki-checkin\profiles\` | `~/.local/share/tanki-checkin/profiles/` |
| лог и состояние | `%LOCALAPPDATA%\tanki-checkin\state\` | `~/.local/state/tanki-checkin/` |

Оба места переопределяются переменными `TANKI_CHECKIN_DATA` и
`TANKI_CHECKIN_STATE`.
